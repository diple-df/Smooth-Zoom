# PERF — модель нагрузки Smooth Zoom 2.8.1

Документ описывает, какая работа выполняется на каждое событие, кадр и мутацию,
и что именно было убрано относительно версии 2.7.0. Плюс список краевых
случаев: что обработано осознанно, что оставлено как ограничение.

## 1. Что было в 2.7.0

| Место | Работа |
|---|---|
| `onWheel` (каждый tick) | `applyTransform()` из обработчика: запись `transition` + `transform` на `<html>` → пересчёт стиля корня на **каждое** событие колеса (до 120–200/с на трекпаде) |
| `onWheel` при зажатом Ctrl | `CONFIG.transitionMs`-переход перезапускался на каждом событии; при панораме `transition` переключался на `0s` и обратно → рывок на стыке + двойная запись свойства |
| `applyTransform` | `toFixed()` дважды за вызов, строка собирается заново даже если ничего не изменилось |
| `enterTransform` | полный скан `document.body.getElementsByTagName('*')` с `getComputedStyle` для каждого узла, **плюс** второй `getComputedStyle` на каждый fixed-элемент для `box-sizing`/padding → 2 × N чтений стиля подряд |
| `convertFixedElements` | запись стилей шла в том же цикле, что и чтения → layout-trashing: после каждой записи следующий `getComputedStyle` форсировал пересчёт |
| `markActiveForCrisp` | `clearTimeout` + `setTimeout` на **каждое** событие колеса |
| `resize` (без зума) | `measure()` — чтения `innerWidth`/`scrollWidth` — на каждое событие ресайза, даже когда масштаб 1 |
| `scroll` | `window.scrollTo(0,0)` с `try/catch` на каждое событие скролла, включая программные |
| fixed-элементы | не восстанавливались при уходе со страницы/печати; `position: fixed` из CSS с `!important` не конвертировался (элемент «улетал» с трансформом) |
| живой DOM | не отслеживался: модалка, появившаяся во время зума, оставалась `fixed` и уезжала вместе с `translate` |

## 2. Что стало: работа по событиям

### Обычная прокрутка (масштаб 1, Ctrl не зажат) — самый частый случай

```
onWheel → e.ctrlKey? нет → transformActive? нет → return
```

2 чтения свойств события, ни одного обращения к DOM/стилям, ни одного
аллока. `preventDefault` не вызывается — нативный скролл не затронут.

### Ctrl+колесо / pinch (один шаг зума)

```
onWheel
├─ должен ли обрабатывать документ (кэш 1 с, при активном зуме — сразу true)
├─ preventDefault + stopPropagation
├─ enterTransform()            — только на первом шаге сессии
├─ нормализация deltaY          — 1–2 сравнения
├─ привязка к курсору           — 8 арифметических операций, 0 чтений layout
├─ clampPan()                   — 4 умножения/сравнения по кэшу размеров
└─ scheduleFrame()              — 1 requestAnimationFrame (если ещё не запланирован)
```

**Ни одной записи стиля и ни одного чтения layout из обработчика события.**
Раньше здесь было 2 записи стиля корня; теперь 0.

### Кадр (не более одного на кадр отрисовки)

```
commitFrame
├─ (если геометрия помечена грязной) measure() + clampPan()
├─ writeTransform()  — 1 setProperty('transform') + при необходимости will-change
├─ armCrisp()        — ставит таймер только если его нет
└─ armExit()         — ставит таймер только если его нет
```

Серия из 10 событий колеса внутри одного кадра даёт **одну** запись
`transform` вместо 10. Дельта накапливается в `scale`/`tx`/`ty` каждым
событием, поэтому сумма шагов та же, что и при записи на каждое событие.

### Панорама колесом (масштаб > 1)

```
onWheel → freezeLive() (только при смене режима зум↔панорама)
        → 2 сложения на дельту → clampPan() → scheduleFrame()
```

`freezeLive()` снимает фактическую матрицу один раз в момент переключения
режима, чтобы незавершённый переход не «допрыгнул» в старую цель. При
непрерывной панораме он не вызывается вовсе (`animOn === false`).

### Мутация DOM (только пока идёт зум)

`MutationObserver` (childList + attributes по `class`/`style`/`hidden`):

- колбэк: обход записей, `WeakSet`-дедупликация, сложение узлов в массив — **без** чтений стиля;
- батч раз в 180 мс: `getComputedStyle` только по добавленным поддеревьям;
- потолок 200 узлов → один полный скан вместо тысяч поддеревьев;
- свои собственные записи (`<html>`, уже сконвертированные элементы) отфильтрованы, петли нет.

### Конец серии (`transitionMs + 80` мс тишины)

- таймер crisp: снимает `will-change` → браузер перерисовывает страницу чётко
  и больше не держит увеличенный слой;
- таймер exit: если `scale === 1` — выход в нативное состояние (снять transform,
  вернуть fixed-элементы и позицию скролла), иначе просто ничего.

Оба таймера не переставляются, пока серия продолжается, и после срабатывания
не пересоздаются.

## 3. Нулевая нагрузка в покое

Когда пользователь не крутит колесо и не панорамирует:

- **rAF-цикла нет** — кадр запрашивается только из обработчика ввода;
- **таймеров нет** — оба одноразовые и после срабатывания не переставляются;
- **наблюдателя нет**, пока не активен зум; во время зума он событийный, а
  колбэк не читает стили;
- **`will-change` снят** — композитор не держит увеличенный слой;
- **чтений layout нет** — все размеры в кэше, обработчик колеса до DOM не дотягивается.

Единственный постоянный слушатель — `wheel` (две проверки свойств на событие)
плюс `blur`. Это цена того, что pinch-жест тачпада приходит без `keydown`
Ctrl и отложенное подключение его пропускало.

## 4. Почему оставлен CSS transition, а не ручной rAF-цикл

| | CSS transition (выбрано) | Ручной rAF |
|---|---|---|
| Плавность при занятом главном потоке | интерполяцию ведёт композитор, кадры не зависят от JS | каждый кадр зависит от планировщика JS → рывки на тяжёлых страницах |
| Работа в главном потоке | 1 запись на событие (с коалесингом — на кадр) | 1 запись на кадр до конца анимации |
| Покой | 0 (анимация уже закончилась) | 0 (цикл останавливается) |
| Привязка к курсору | точная в конечной точке; в промежутке обе величины идут с одной функцией плавности, поэтому расхождение затухает | точная на каждом кадре |

Выбран композитор: «плавность даже на тяжёлых страницах» — исходное обещание
скрипта, и оно важнее микролага в середине перехода. Панорама идёт 1:1
(`transition: none`), зум — с переходом; переключение режимов происходит только
на границе режима и через «заморозку» фактической матрицы, поэтому стык не
виден.

## 5. Привязка к курсору: формула

Модель преобразования:

```
viewport = origin + translate + scale * local
```

- `local` — координаты внутри border-box `<html>` при `scroll = 0`;
- `origin` — положение этого border-box в окне при `scroll = 0` (учитывает
  `margin` на `<html>`);
- `translate` (`tx`,`ty`) — ровно то, что пишется в `translate3d(...)`.

Шаг зума к точке (`clientX`,`clientY`):

```
ux = clientX - origin
local = (ux - tx) / scale          // точка документа под курсором
scale' = clamp(scale * k)
tx' = ux - local * scale'          // та же точка снова под курсором
```

Подстановка: `origin + tx' + scale' * local = origin + ux = clientX`. Точка
остаётся под курсором точно, без накопления дрейфа за серию шагов (проверено
численно, см. раздел 7).

Вход в зум из прокрученного состояния: `tx = -scrollX`, `ty = -scrollY`,
затем `scrollTo(0,0)`. Картинка не меняется: `origin + (-scroll) + 1*local`
ровно совпадает с `origin + local - scroll` до входа.

Выход: `scrollTo(-tx/scale, -ty/scale)` — при `scale = 1` это `-tx`, то есть
ровно прежняя позиция прокрутки.

## 6. Краевые случаи

### Обработано

| Случай | Что сделано |
|---|---|
| Страница была прокручена | вход компенсирует скролл, выход возвращает точную позицию |
| `margin`/`border` на `<html>` | `origin` измеряется по факту, а не считается нулём (в 2.7.0 это давало сдвиг `2 × margin`) |
| `margin` на `<body>` | не влияет: body внутри border-box `<html>`, координаты общие |
| `scroll-behavior: smooth` | на время сессии принудительно `auto`, затем восстанавливается; иначе `scrollTo(0,0)` анимировался бы и ломал вход |
| `overflow: hidden` на html/body | `scrollWidth == clientWidth`, зум работает как по холсту, панорама ограничена видимой областью |
| Контент меньше окна | прижимается к верхнему/левому краю, как нативный скролл; пустоты не появляется |
| Огромные дельты (игровая мышь, pinch) | множитель ограничен `[0.15, 4]` за событие — масштаб не перескакивает через весь диапазон |
| Быстрая смена направления | дельты складываются в целевое состояние; границы проверяются на каждом шаге |
| Курсор у края страницы | привязка упирается в границу панорамы (иначе появилась бы пустая область) |
| fixed с `!important` в CSS | переопределяется через `setProperty(..., 'important')`, при выходе возвращается и значение, и приоритет |
| fixed со своим `transform` | размеры не переписываются (rect уже искажён), позиция калибруется по факту |
| fixed, вложенный в fixed | вложенный не конвертируется — у него уже другой `offsetParent` |
| Скрытый (`display:none`) fixed | пропускается (нулевой бокс); показ ловится наблюдателем по `class`/`style`/`hidden` |
| Модалка/тост появились во время зума | наблюдатель конвертирует их в пределах 180 мс |
| Страница доросла (ленивые картинки, лента) | границы обновляются после скана, кадр пишется только при реальном изменении размера |
| Печать / уход со страницы | `beforeprint` и `pagehide` выводят в нативное состояние, чтобы в bfcache не осталась трансформированная страница |
| Потеря фокуса окна | выход в нативное состояние |
| `sticky` | сознательно не конвертируется: `absolute` вырвал бы элемент из потока и контент под ним прыгнул бы |
| SPA-переход | зум сохраняется (пользователь всё ещё в нём), новые fixed-элементы ловятся наблюдателем; выход — по возврату к масштабу 1 |
| `html`/`body` уже с `transform` или CSS `zoom` на `<html>` | страница не трогается: наш transform перезаписал бы чужой, и привязка поехала бы. Проверка кэшируется на 1 с |
| Ctrl + / − (родной зум) | не перехватывается: обрабатывается только `wheel` |

### Осознанные ограничения

1. **Курсор у самого края** — привязка ограничена границей панорамы. Точное
   удержание потребовало бы пустой области за краем страницы; выбрано
   поведение нативного зума.
2. **Страница короче окна** — по короткой оси привязки нет (нечего двигать),
   контент остаётся у верхнего/левого края.
3. **`position: sticky`** во время зума ведёт себя как обычный поток: скролл
   зафиксирован в 0, поэтому «прилипание» не активируется.
4. **Вложенные скроллеры** (`div` со своим скроллом) во время зума не
   прокручиваются: колесо уходит в панораму. Так было и в 2.7.0.
5. **Сайты, которые сами обрабатывают Ctrl+колесо** (карты, CAD) — событие
   перехватывается скриптом в capture-фазе.
6. **`transform`/`zoom` на `<html>`** — документ не обрабатывается (см. выше).
7. **Доли пикселя при выходе** — масштаб у нижней границы фиксируется ровно в 1,
   поэтому остаточного сдвига при возврате к нативной прокрутке нет.

## 7. Как проверялось без браузера

- `node --check` — синтаксис.
- Численная модель привязки: одиночный шаг, серия с движущимся курсором,
  зум внутрь-обратно, вход со скроллом, ненулевой `origin`, край страницы,
  короткая страница, 600 событий подряд — все проверки на допуск `1e-9`.
- Симуляция жизненного цикла на фейковом DOM: вход, конвертация fixed
  (включая `position: fixed` в inline-стиле), возврат к масштабу 1, полное
  восстановление стилей и позиции скролла, отсутствие работы на обычной прокрутке.
